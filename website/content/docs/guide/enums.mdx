title: Enums
description: Define enum values and use them in fields and arguments.
---

A GraphQL enum defines a fixed set of named values. `builder.enumType` returns a reference you can
use as a field or argument type.

## Defining an enum

An array of strings uses the same values in GraphQL and in your resolvers:

<include cwd lang="typescript" meta='playground example="types-enums"'>playground-examples/types-enums/schema.ts#schema</include>

Pothos infers the inline array as the literal values `'Feet' | 'Meters'`. If you define the array
in a separate variable, use `as const` to retain those literal types.

<include cwd lang="graphql" meta='playground example="types-enums"'>playground-examples/types-enums/query.graphql</include>

```json
{
  "data": {
    "height": 5,
    "feet": 16.405,
    "unit": "Meters"
  }
}
```

Enum literals in a query are unquoted names. When passing an enum in JSON variables, use a string
such as `"Meters"`. Select the companion's `variables` operation, change the unit to `"Feet"`
in its Variables tab, and run again.

## Descriptions and internal values

Use a values object to describe or deprecate individual values, or to map GraphQL names to different
values in your application:

<include cwd lang="typescript" meta='playground example="types-enum-species"'>playground-examples/types-enum-species/schema.ts#definition</include>

The keys are GraphQL names. An argument containing `Northern` reaches the resolver as
`'camelopardalis'`; returning `'camelopardalis'` from a `GiraffeSpecies` field produces `"Northern"`
in the response. If `value` is omitted, the key is also the internal value. Deprecating a value
leaves it usable by clients.

## TypeScript enums

If your application already uses a TypeScript enum, register it directly:

<include cwd lang="typescript" meta='playground example="types-enum-diet"'>playground-examples/types-enum-diet/schema.ts#definition</include>

The enum's keys become GraphQL value names. Resolvers receive and return the TypeScript enum's
values, including numeric values in this example. You can use either the TypeScript enum itself
or the reference returned by `enumType` as the field or argument type.

You can also derive enum values from an existing object:

<include cwd lang="typescript" meta='playground example="types-enum-objects-variant-values" tab="Values as names"'>playground-examples/types-enum-objects/variant-values/schema.ts#definition</include>

<include cwd lang="typescript" meta='playground example="types-enum-objects-variant-keys" tab="Keys as names"'>playground-examples/types-enum-objects/variant-keys/schema.ts#definition</include>

In **Mapped values**, the GraphQL names are `sedan`, `suv`, `truck`, and `motorcycle`, while resolvers
use `SEDAN`, `SUV`, `TRUCK`, and `MOTORCYCLE`.

**Values as names** uses `Object.values(VehicleType)` for both names and internal values.
**Keys as names** uses `Object.keys(VehicleType)` for both. TypeScript types `Object.keys` as
`string[]`, so the assertion preserves the known keys of this local object.

Open each tab in the playground and compare `vehicle` with `internalValue`: the first is the
GraphQL enum name, while the second exposes the value the argument resolver receives.
