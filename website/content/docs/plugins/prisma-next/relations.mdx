---
title: Relations
description: Adding relations to Prisma-backed types
---

`t.relation` exposes a relation from the contract:

```ts
builder.prismaObject('User', {
  fields: (t) => ({
    id: t.exposeID('id'),
    email: t.exposeString('email'),
    posts: t.relation('posts'),
  }),
});

builder.prismaObject('Post', {
  fields: (t) => ({
    id: t.exposeID('id'),
    title: t.exposeString('title'),
    author: t.relation('author'),
  }),
});
```

To-many relations are non-null lists. A to-one relation is non-null when its foreign key is
non-null, unless it has a `query` or a variant `type`, either of which can filter the row out. Pass
`nullable` to override.

## Filtering and sorting

`query` accepts `{ where, orderBy, limit, offset }`, or a function of the field's arguments and
context returning one. A to-one relation's `query` takes only `where`.

```ts
posts: t.relation('posts', {
  args: { oldestFirst: t.arg.boolean() },
  query: (args) => ({
    orderBy: (post) => (args.oldestFirst ? post.createdAt.asc() : post.createdAt.desc()),
  }),
}),
```

For a to-many relation, the `query` function can also return a function that takes the relation's
Collection and returns a refined one, for example to apply a fragment:

```ts
const published = db.orm.Post.fragment((posts) => posts.where({ published: 1 }));

posts: t.relation('posts', {
  query: () => (posts) => posts.with(published).orderBy((post) => post.createdAt.desc()),
}),
```

With `AsyncSelections: true` in the builder's types, the function can be async.

## Counts and other aggregates

```ts
builder.prismaObject('User', {
  fields: (t) => ({
    postCount: t.relationCount('posts'),
    publishedPostCount: t.relationCount('posts', { where: { published: 1 } }),
    postCountByState: t.relationCount('posts', {
      args: { published: t.arg.int({ required: true }) },
      where: (args) => ({ published: args.published }),
    }),
  }),
});
```

`where` takes the same values as a relation's `query.where`, or a function of the arguments and
context returning one. A count is always a non-null `Int`, so an auth check that denies it nulls the
parent. To hide a count from some users, use a nullable field with a `select`, as below.

For other aggregates, give a field a `select` function. It receives the relation's Collection. Each
key it returns is added to the parent row, and must be a literal string:

```ts
builder.prismaObject('User', {
  fields: (t) => ({
    latestPostTitle: t.field({
      type: 'String',
      nullable: true,
      select: { posts: { orderBy: (post) => post.createdAt.desc(), limit: 1 } },
      resolve: (user) => user.posts[0]?.title ?? null,
    }),
    postStats: t.field({
      type: 'String',
      select: {
        posts: (posts) => ({ total: posts.count(), score: posts.sum('score') }),
      },
      resolve: (user) => `${user.total} posts, score ${user.score}`,
    }),
  }),
});
```

## Many-to-many

Relations defined with `rel.manyToMany({ through, from, to })` work with `t.relation`. To expose
columns on the junction, model it as its own model and use two relations.

## Returning rows from other fields

A plain `t.field` that returns a model's type must return the primary key and the columns and
to-one relations in the type's `select`. `typeof User.$inferType` is that row type. For a model
without a primary key, return the whole row.
