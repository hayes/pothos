## Defining types

`builder.prismaObject` takes a contract model name and the usual object type options. Column types
are inferred from the contract.

```ts
builder.prismaObject('User', {
  // Optional, defaults to the model name
  name: 'PostAuthor',
  fields: (t) => ({
    id: t.exposeID('id'),
    email: t.exposeString('email'),
  }),
});
```

Each model has one primary type, which `type: 'User'` and `t.relation` refer to. Add fields to it
with [`prismaObjectFields`](#adding-fields), or define more types for the same model with
[`variant`](./variants).

## Prisma fields

`t.prismaField` resolves to an unexecuted Collection. The plugin adds the selection for the query
and runs it.

```ts
builder.queryType({
  fields: (t) => ({
    me: t.prismaField({
      type: 'User',
      nullable: true,
      resolve: (_root, _args, ctx) => ctx.db.orm.User.where((user) => user.id.eq(ctx.userId)),
    }),
  }),
});
```

Don't call `.all()`, `.first()` or `.include()` on the Collection. To filter a relation, use its
field's [`query`](./relations#filtering-and-sorting).

### Mutations

Perform the write, then return a Collection for the result:

```ts
builder.mutationType({
  fields: (t) => ({
    renameUser: t.prismaField({
      type: 'User',
      args: {
        id: t.arg.id({ required: true }),
        firstName: t.arg.string({ required: true }),
      },
      resolve: async (_root, args, ctx) => {
        const user = ctx.db.orm.User.where({ id: String(args.id) });
        await user.update({ firstName: args.firstName });
        return user;
      },
    }),
  }),
});
```

See [Transactions](./setup#transactions) to run the write and the reads in one transaction.

### Payloads

A payload type can hold the result's ID and load it with a `t.prismaField`:

```ts
const RenameUserPayload = builder.objectRef<{ userId: string }>('RenameUserPayload').implement({
  fields: (t) => ({
    user: t.prismaField({
      type: 'User',
      resolve: (payload, _args, ctx) => ctx.db.orm.User.where({ id: payload.userId }),
    }),
  }),
});
```

To load the result with the write itself, apply the selection with `collectionFromInfo`. `path`
leads from the field to the rows, and `typeName` picks the type when it leads to an interface or
union. This works for writes that return the row, such as `update` or `delete`:

```ts
import { collectionFromInfo } from '@pothos/plugin-prisma-next';

const RenameUserPayload = builder.objectRef<{ user: unknown }>('RenameUserPayload').implement({
  fields: (t) => ({ user: t.field({ type: User, nullable: true, resolve: (p) => p.user as never }) }),
});

builder.mutationField('renameUser', (t) =>
  t.field({
    type: RenameUserPayload,
    args: { id: t.arg.id({ required: true }), firstName: t.arg.string({ required: true }) },
    resolve: async (_root, args, ctx, info) => {
      const users = await collectionFromInfo({
        collection: ctx.db.orm.User.where({ id: String(args.id) }),
        context: ctx,
        info,
        path: ['user'],
      });
      return { user: await users.update({ firstName: args.firstName }) };
    },
  }),
);
```

### Subscriptions

`resolve` receives each value `subscribe` yields and returns a Collection to load it from:

```ts
builder.subscriptionType({
  fields: (t) => ({
    userChanged: t.prismaField({
      type: 'User',
      nullable: true,
      subscribe: (_root, _args, ctx) => ctx.pubsub.subscribe('userChanged'),
      resolve: (id, _args, ctx) => ctx.db.orm.User.where({ id }),
    }),
  }),
});
```

## Selections

`select` on the type loads data whenever the type is queried; `select` on a field loads it when
that field is queried. The primary key is always loaded.

```ts
builder.prismaObject('User', {
  select: { firstName: true, lastName: true },
  fields: (t) => ({
    fullName: t.string({
      resolve: (user) => `${user.firstName} ${user.lastName}`,
    }),
    initials: t.string({
      select: ['firstName', 'lastName'],
      resolve: (user) => `${user.firstName[0]}${user.lastName[0]}`,
    }),
    publishedPostCount: t.field({
      type: 'Int',
      select: {
        posts: (posts) => ({ publishedCount: posts.where({ published: 1 }).count() }),
      },
      resolve: (user) => user.publishedCount,
    }),
  }),
});
```

A `select` accepts:

- `{ column: true }` or `['column']`: a column.
- `{ relation: true }`: the related rows.
- `{ relation: { where, orderBy, limit, offset } }`: filtered or sorted related rows. A to-one
  relation takes only `where`, and only in a field's `select`.
- `{ relation: (collection) => ({ ... }) }`: counts or aggregates of a to-many relation. Each key is
  added to the parent row, so it can't reuse a column or relation name.

Read computed keys with a resolver; `t.expose*` only works on columns.

To filter a to-one relation, use the object form in a field's `select`. The result can be `null`
even when the foreign key is required:

```ts
authorName: t.string({
  nullable: true,
  select: { author: { where: { firstName: 'Alice' } } },
  resolve: (post) => post.author?.firstName ?? null,
}),
```

A field's `select` can also be a function of its arguments and context. With `AsyncSelections: true`
in the builder's types, it can be async. Columns selected by only some branches are optional on the
parent:

```ts
email: t.string({
  nullable: true,
  select: (_args, ctx) => (ctx.isAdmin ? { email: true, firstName: true } : { firstName: true }),
  resolve: (user) => user.email ?? null,
}),
```

Type-level checks such as `authScopes` can rely on the key and the columns and to-one relations of
the type's `select`. Anything else may not be loaded yet, unless the row came from a prisma field,
relation or connection.

## Adding fields

`builder.objectField` doesn't support `select`. Use `prismaObjectField` or `prismaObjectFields`
instead:

```ts
builder.prismaObjectField('User', 'displayName', (t) =>
  t.string({
    select: ['firstName', 'lastName'],
    resolve: (user) => `${user.firstName} ${user.lastName}`,
  }),
);
```

Pass the ref returned by `prismaObject` instead of the model name to read the type's `select` in
the parent, or to extend a [variant](./variants):

```ts
const User = builder.prismaObject('User', {
  select: ['firstName'],
  fields: (t) => ({ id: t.exposeID('id') }),
});

builder.prismaObjectField(User, 'displayName', (t) =>
  t.string({
    select: ['lastName'],
    resolve: (user) => `${user.firstName} ${user.lastName}`,
  }),
);
```
