<Callout type="warn" title="Experimental">
  This plugin targets Prisma ORM `8.0.0-rc.22` exactly. Its API, and Prisma's, may change in any
  release.
</Callout>

The Prisma Next plugin lets you build GraphQL types from the models in a
[Prisma ORM 8](https://github.com/prisma/orm) contract. Query fields load a model's rows, and the
plugin adds the columns and relations each GraphQL query asks for in one statement. It supports
relations, counts, variants, interfaces, and Relay nodes and connections.

For Prisma ORM 7, use [`@pothos/plugin-prisma`](/docs/plugins/prisma) instead. The two can't be installed
in the same project.

The [playground example](/playground?example=plugin-prisma-next) runs the examples below against
SQLite in the browser, and its **SQL** tab shows the statements each query runs.

For `{ users { fullName posts { title author { email } } } }`, the users, their posts, and each
post's author load in one SQL statement. Each root field usually runs as one statement, with its
relations, counts and connection pages included.

## Relay connections

With the [Relay plugin](/docs/plugins/relay), `t.relatedConnection` turns a relation into a
paginated connection:

<include cwd lang="typescript" meta='playground example="plugin-prisma-next" query="{ users { fullName postConnection(first: 1) { totalCount edges { node { title } } pageInfo { endCursor hasNextPage } } } }"'>playground-examples/plugin-prisma-next/types/user.ts#user-post-connection</include>

`t.prismaConnection` does the same for query fields. See
[Connections](/docs/plugins/prisma-next/connections).

## Coming from plugin-prisma

- Rows hold the primary key and what the query selects, not every column. `t.expose*` loads its
  own column, but a resolver that reads a column must list it in a
  [`select`](/docs/plugins/prisma-next/objects#selections).
- `t.relationCount` filters with `query: { where }` instead of `where`.
- `t.prismaField` takes `collection`, `query` or `resolve`. `resolve` gets the model's Collection
  with the selection already planned, and runs it
  (see [Mutations](/docs/plugins/prisma-next/objects#mutations)).
- Connections take no `cursor`. They order by `query.orderBy` and add a unique key
  (see [Ordering and cursors](/docs/plugins/prisma-next/connections#ordering-and-cursors)).
- `t.prismaConnection` has no `resolve`. For custom logic, use `t.connection` with the connection
  helpers' `load` and `resolve`
  (see [Before or after loading](/docs/plugins/prisma-next/connections#before-or-after-loading)).
- `t.relation` has no `resolve`. Use `t.field` with a `select`, and
  [`nestedSelection`](/docs/plugins/prisma-next/indirect-relations) to load the relation's own
  selections.
- `nestedSelection` takes an object, `{ query, path, type }`, instead of positional arguments.
- A field returning a model's type must return rows the plugin planned, typed `Planned<'User'>`.
  Rows from a plain ORM query are a type error
  (see [Returning rows from other fields](/docs/plugins/prisma-next/relations#returning-rows-from-other-fields)).
