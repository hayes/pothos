---
title: Interfaces
description: GraphQL interfaces backed by contract models
---

Use `builder.prismaInterface` to define a GraphQL interface backed by a model. It takes the same
options as `builder.prismaObject`. The objects that implement it must use the same model, or one of
its [variant models](#native-inheritance).

Here admins and regular users share a `Person` interface. `resolveType` picks the type from the
email, so the interface lists `email` in its `select`:

```ts
const Person = builder.prismaInterface('User', {
  variant: 'Person',
  select: ['email'],
  resolveType: (user) => (user.email.endsWith('@admin.example.com') ? 'Admin' : 'User'),
  fields: (t) => ({
    id: t.exposeID('id'),
    firstName: t.exposeString('firstName'),
  }),
});

builder.prismaObject('User', {
  interfaces: [Person],
  fields: (t) => ({
    posts: t.relation('posts'),
  }),
});

builder.prismaObject('User', {
  variant: 'Admin',
  interfaces: [Person],
  fields: (t) => ({
    email: t.exposeString('email'),
  }),
});

builder.queryFields((t) => ({
  people: t.prismaField({
    type: [Person],
    query: (_root, _args, ctx) => ctx.db.orm.User,
  }),
}));
```

`t.prismaField`, `t.prismaConnection`, `t.relation` and `t.relatedConnection` all accept an
interface ref as `type`. Fields on an implementing type can read the interface's `select`.
Implementing objects don't accept `isTypeOf`.

`resolveType` sees the columns and to-one relations in the interface's `select`, but not its to-many
relations, counts or aggregates.

To add fields to the interface from another file, use `prismaInterfaceField` or
`prismaInterfaceFields`:

```ts
builder.prismaInterfaceField(Person, 'displayName', (t) =>
  t.string({
    select: ['firstName', 'lastName'],
    resolve: (person) => `${person.firstName} ${person.lastName}`,
  }),
);
```

To return rows through `Node` or another interface from a plain field, see
[Returning rows from other fields](./relations#returning-rows-from-other-fields).

An object type from `builder.objectRef` can implement a `prismaInterface` if its shape includes
`PlannedRowBrand` for the model, such as `builder.objectRef<{ id: string } & PlannedRowBrand<'User'>>`.

## Native inheritance

If your contract uses variant models (a base model with a discriminator column), register the base
model with `prismaInterface` and each variant with `prismaObject`. Each row resolves to its
variant's type by the discriminator, so you don't need a `resolveType`. In this example, `Bug` is a
variant of `Task`:

```ts
const Task = builder.prismaInterface('Task', {
  fields: (t) => ({
    id: t.exposeID('id'),
    owner: t.relation('owner'),
  }),
});

builder.prismaObject('Bug', {
  interfaces: [Task],
  fields: (t) => ({
    severity: t.exposeString('severity'),
  }),
});

builder.queryType({
  fields: (t) => ({
    tasks: t.prismaField({
      type: [Task],
      query: (_root, _args, ctx) => ctx.db.orm.Task,
    }),
    bugs: t.prismaField({
      type: ['Bug'],
      query: (_root, _args, ctx) => ctx.db.orm.Task.variant('bug'),
    }),
  }),
});
```

- Load a variant's rows with `ctx.db.orm.Task.variant('bug')`, not `ctx.db.orm.Bug`, which Prisma
  doesn't filter by the discriminator.
- Each variant needs exactly one implementing type, unless the interface has a `resolveType`.
- A relation declared on a variant can't be in the variant type's `select`. Use a field's `select`
  or `t.relation`.
- A relation to a variant with its own table can only filter and sort on the variant's own fields,
  and only a field of the variant's object type can return its rows. Loading them in a type's
  `select` or another field's `select` fails the schema build (a `select` function fails the
  request).
- A relation to a variant that shares the base's table can't return an interface whose `select`
  loads a base model relation.
- Pass a variant's ref as `type` to `t.relation` or `t.relatedConnection` to return only that
  variant's rows. In a `select`, use the ref as the relation's entry: `select: { tasks: Bug }`.
  `{ tasks: true }` loads every task.
- A row returned from a plain `t.field` must be
  [planned](./relations#returning-rows-from-other-fields) and hold the discriminator.
