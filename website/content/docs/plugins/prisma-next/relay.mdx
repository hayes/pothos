Nodes require the [Relay plugin](./setup#installing). [Connections](./connections) covers
pagination.

## Define a node

`builder.prismaNode` takes the same options as `builder.prismaObject`, plus an `id`:

```ts
builder.prismaNode('Post', {
  id: { field: 'id' },
  fields: (t) => ({
    title: t.exposeString('title'),
    author: t.relation('author'),
  }),
});
```

- `id.field`: a column, or a list of columns. They must include a complete non-null primary or
  unique key; otherwise the schema build fails.
- `id.parse` / `id.resolve`: custom parsing and serialization of the ID. By default IDs are
  encoded with the client's column codecs and decoded back to the column's values, which is also
  what `t.arg.globalID({ for: NodeRef })` receives. An encoded ID can be at most 2048
  characters, so a row with a very long string key fails its `id` field. If `id.resolve` returns
  anything other than the key's own value (for example `comment:${id}`), also provide `id.parse`
  to turn it back into the key's values; otherwise `node(id:)` finds no row and returns `null`.
- `collection`: the Collection nodes load from, or a function of the context returning one, to
  apply per-request filters. Defaults to the model's collection on the plugin's `client`.

`node` and `nodes` lookups with the same path are batched into one query, with the selection
applied.

## Several node types for one model

Use `isTypeOf` to decide which type a row belongs to. It can only read columns in the type's
`select`:

```ts
builder.prismaNode('Post', {
  variant: 'DraftPost',
  id: { field: 'id' },
  select: ['published'],
  isTypeOf: (post) => post.published === 0,
  fields: (t) => ({ title: t.exposeString('title') }),
});
```
