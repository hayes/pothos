title: Relay nodes
description: Defining Relay nodes for contract-backed models

Nodes require the [Relay plugin](./setup#installing). [Connections](./connections) covers
pagination.

## Define a node

`builder.prismaNode` takes the same options as `builder.prismaObject`, plus an `id` and the
Collection to load nodes from:

```ts
builder.prismaNode('Post', {
  id: { field: 'id' },
  collection: (ctx) => ctx.db.orm.Post,
  fields: (t) => ({
    title: t.exposeString('title'),
    author: t.relation('author'),
  }),
});
```

- `id.field`: a column, or a list of columns. They must include a complete non-null primary or
  unique key; otherwise the schema build fails.
- `id.parse` / `id.resolve`: custom parsing and serialization of the ID.
- `id.codecs`: `{ encode, decode }` per ID column, for object values such as Temporal
  identifiers.
- `collection`: a Collection, or a function of the context returning one. Use the function to
  apply per-request filters.

`node` and `nodes` lookups with the same path are batched into one query, with the selection
applied.

## Several node types for one model

Use `isTypeOf` to decide which type a row belongs to. It can only read columns in the type's
`select`:

```ts
builder.prismaNode('Post', {
  variant: 'DraftPost',
  id: { field: 'id' },
  collection: (ctx) => ctx.db.orm.Post,
  select: ['published'],
  isTypeOf: (post) => post.published === 0,
  fields: (t) => ({ title: t.exposeString('title') }),
});
```
