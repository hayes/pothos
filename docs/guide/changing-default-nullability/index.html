Default nullability

Configure schema-wide defaults and override them for individual fields.

By default, Pothos output fields are nullable, and arguments and input object fields are optional. Use nullable: false to make an output field non-null, or required: true to require an input.

You can change these defaults for a builder. Set each default in both the SchemaTypes generic for TypeScript checking and the constructor options for runtime schema generation:

These settings are independent: omit the input setting from both places if you only want to change output nullability, or omit the output setting to change only input requiredness.

The example produces these field types:

nullable: true and required: false override the new defaults on individual fields. List items remain non-null by default; changing the builder defaults controls the list itself. Use the object forms of nullable or required to configure items separately, as shown in Fields and Arguments.

Changing defaults changes the public schema for fields without explicit settings. Requiring an existing optional argument or input field can break client requests. Non-null output fields also change error propagation: if a resolver returns null or throws, GraphQL propagates the null to the nearest nullable parent, potentially making the entire response's data null.

For example, if nickname's resolver throws new Error('Nickname unavailable'), nullable: true makes only nickname null. Without that override, the builder's non-null default makes the whole response's data null.
