Fields in a fragment on an interface with no table (`... on Node` beneath a drizzle interface) are loaded by the parent query, along with the type-level selects of the variants they cover (the whole row, for a variant with none), unless those selects conflict with each other, or with a field-level select elsewhere in the query while every field in the fragment has a select of its own. In that case a field with its own select loads separately. A field relying on conflicting variants' type-level selects does not get those columns. When only a field-level select conflicts and the fragment holds a field with no select, that field-level select reloads per row instead. A `query` callback reads `pathInfo` for the path it is really at, so reading it costs one planning pass per path beneath such fragments; a callback that does not read it costs one pass per field. Temporal values in query arguments no longer throw. `Map`, `Set` and other instances with no enumerable state compare through their `equals`, or by identity when they have none, and typed arrays compare by type and bytes, so a `Buffer` no longer equals a `Uint8Array`.
